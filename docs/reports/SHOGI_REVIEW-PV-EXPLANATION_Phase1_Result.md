# SHOGI_REVIEW-PV-EXPLANATION Phase 1 実施結果

## 実施概要

- 監査対象: `origin/main` / `76ad3226f7c36ee9f1df370787b4c5de713e117e`
- 解析条件: YaneuraOu V9.00 NNUE + 水匠5、1局面30,000 nodes（変更なし）
- 対象局: NAGATA2532 vs sonao81、2026/09/11 14:32、62手、後手勝ち
- 方針: 評価値、エンジンPV、合法手、盤上の駒、王手、駒取り、成り、mate scoreだけを説明根拠にした。

## Phase 0 監査結果

旧解析JSONはschemaVersion 1で、評価値は先手視点の`cp`だけ、課題局面のPVはUSI列だけだった。コメントは局面から検証していない「受け」「玉が薄い」などの定型文を含み、mate scoreは通常のcentipawnへ約30,000点として写像されていた。

NAGATA2532戦28手目の旧保存値は、実戦手`5c4d`、推奨手`1c6h+`、先手視点`-706 → -241`、後手の損失465、PV`1c6h+ 7i6h`だった。後手視点へ直すと`+706 → +241`である。

## 実装結果

- 解析JSONをschemaVersion 2へ拡張し、全指し手に`scoreBefore`、`actualMove`、`scoreAfterActual`、`bestMove`、`bestScore`、`pv`を保存した。従来グラフ用の先手視点`cp`も維持した。
- scoreは`cp`と`mate`を構造化して保持し、同一尺度としてUI表示しないようにした。
- エンジンが実際に返したPVを保存し、局面へ1手ずつ適用して、▲/△、同、成、不成、打、方向修飾を含む日本語表記を生成した。
- 実戦手側は、実戦手と次局面で既に取得済みの30,000 nodes PVを接続した。追加探索なしで実戦分岐を比較できるため、従来の解析条件と検索回数を変えていない。
- ポイントはPVから機械的に確認できた成り、駒取り、王手、詰み評価だけを最大2件表示する。該当事実がなければ、推奨手と読み筋の比較を促す中立文だけを表示する。
- iPhone向けカードは実戦手/推奨手、評価値変化、短いポイントを基本表示にし、最大7手のPV比較を`読み筋を見る`へ折りたたんだ。既存の赤=実戦、緑=推奨、盤面反転、座標、次の課題局面を維持した。
- schemaVersion 1の既存解析JSONは従来フィールドへフォールバックする。

## 残課題

推奨PVはエンジンが実際に返した2手だけを表示している。5手へ満たすための手を生成・補完してはいない。将来、30,000 nodesという各探索条件を維持したまま分岐ごとの追加探索を行えば、表示できるPVが長くなる可能性があるが、解析時間は増える。
