# 将棋コーチング・成長記録ツール SSOT

更新日: 2026-09-13

## 1. 背景
ユーザーは将棋ウォーズ（初段）や棋桜（2級）等で対局しているが、上達を実感しにくい。

## 2. 最上位目的
対局棋譜を毎回蓄積し、繰り返す癖・得意不得意・戦法/戦型傾向・課題局面を明らかにする。課題を次局で実践し、達成できたかを継続判定して、改善・横ばい・悪化・新課題を確認できる「将棋コーチング・成長記録ツール」を作る。

中心ループ:
`棋譜保存 → 分析 → 課題発見 → 課題設定 → 次局で実践 → ○/×/－判定 → 成長確認 → 課題更新`

## 3. 成功条件
30局程度継続利用したとき、次の4点が分かること。
1. 自分が何を苦手としているか
2. 次局で意識すべき課題が1〜3件
3. 各課題が改善しているか
4. 同じ失敗の過去局面を盤面で見返せること

## 4. 必須プロダクト要件
- 対局後、iPhone等からクリップボードの棋譜を簡単に貼り付けて保存できる。
- 解析失敗時でも原棋譜を失わず、再解析できる。
- 課題局面で実戦手と推奨手を盤面・通常棋譜表記で比較できる。
- 「この手の問題」「推奨手なら何が変わるか」「次回何を確認するか」を日本語で説明する。
- 説明は保存棋譜・合法手・検証済みエンジン証拠等から裏付けられる内容に限定し、棋風や心理を単一局面から捏造しない。
- 最近10局/30局/全期間を横断し、戦法/戦型、頻出課題、得意不得意、改善傾向、新規課題を集計する。
- 現在の課題は原則最大3件。各対局で `○ 達成 / × 未達成 / － 判定機会なし` を根拠局面付きで判定する。
- 自分・対局相手の棋力推定は参考情報として扱い、公式段級位と区別する。単局から真の棋力を断定しない。

## 5. エンジンの位置付け
YaneuraOu + 水匠5は「正確な評価値を見せること」が目的ではない。学習価値のある局面、実戦手との比較候補、検証可能な戦術的事実を発見する内部センサーとして使う。

評価値・PV・nodesの精度改善だけを目的とする作業は、ユーザーの課題発見・実践・改善確認に直接寄与しない限り優先しない。

## 6. ロードマップ
### P0 Phase 0 — 方針SSOT
この文書を開発判断のSSOTとする。Issue/PRは「中心ループのどこを改善するか」を明記する。

### P0 Phase 1 — 棋譜を絶対に失わない
貼付後、解析開始より先に原棋譜を永続保存する。保存状態と解析状態を分離し、失敗ジョブを元KIFから重複なしで再解析できるようにする。

### P0 Phase 2 — 解析パイプライン安定化
`保存 → queue → worker → engine → artifacts → publish → completed → Pages` を安定化する。Windows worker障害 Issue #5 はこのPhaseのブロッカーとして扱う。

### P1 Phase 3 — 1局レビュー完成
各局最大3〜5の学習価値の高い局面を表示し、実戦手・推奨手・日本語理由・次回の確認事項を提示する。既存B-strict/Reason Evidence/棋譜ビューアーを流用する。

### P1 Phase 4 — 課題管理
分析から候補課題を作り、現在の課題を最大3件に絞る。課題には判定条件と根拠を持たせる。

### P1 Phase 5 — 課題達成判定
各局で課題を○/×/－判定し、根拠局面へ戻れるようにする。判定機会なしを成功扱いしない。

### P1 Phase 6 — 10/30局横断分析
戦法/戦型、頻出ミス、得意不得意、課題の再発率を統計化する。棋風ラベルは事実データから説明可能な場合のみ補助表示する。

### P2 Phase 7 — 成長ダッシュボード
改善/横ばい/悪化/新課題、課題達成率、最近10/30局の変化をホームで確認できるようにする。

### P2 Phase 8 — 棋力推定
教師データの量・多様性ゲートを満たしてから、自分/相手、全体/序盤/中盤/終盤の推定段級位を参考表示する。公式段級位と明確に分離する。

### P3 Phase 9 — PCレス化
ツールの学習価値が成立した後、Windows workerをクラウド解析へ移す費用・速度・運用メリットを評価する。現時点では最優先にしない。

## 7. 当面保留するもの
- Cloud Run等への即時移行
- nodes/PV長だけを目的とした探索量増加
- 既存棋譜の大量再解析
- 教師データ不足状態でのproduction段級位表示
- 評価値中心のUI拡張

## 8. 開発判断ルール
新規Issueは必ず次を答える。
> この変更は「課題発見 → 実践 → 改善確認」のどこを改善するか？

直接寄与しない場合は原則P3以下または保留とする。

実行環境を必ず `☁️ Cloud可 / 🖥️ PC必須 / 🔀 Hybrid` で分類する。

Issueを仕様・実行指示・受入条件・結果のSSOTとし、完了/停止を問わず結果をIssueコメントへ記録する。

## 9. 現在の既存資産
重要局面抽出、B-strict、Reason Evidence、実戦手/推奨手表示、盤面ビューアー、YaneuraOu+水匠5解析、PWA棋譜投入、queue/worker、棋力推定用データ収集基盤は原則再利用する。目的変更を理由に作り直さない。
